## 1. Overview

Billing turns a subscription plan into a financial obligation. Every month, each active service
account receives one invoice. The invoice is a **debit** in the subscriber's ledger.

The most critical correctness requirements for this phase:
1. **Duplicate prevention** — Running the billing job twice in the same month must produce exactly one invoice per service account.
2. **Idempotency** — The billing job should be safe to re-run after a failure without creating duplicates.
3. **Never delete invoices** — A voided invoice gets a new "void" record that reverses the ledger entry. The original invoice row stays in the database forever.

**Instructor checkpoint:** CP3 — Financial Core

## 2. Money Handling Rule (Mandatory)

```
ALL monetary values are stored as integers in centavos.
PHP 999.00 → stored as 99900 (integer)
PHP 0.50   → stored as 50 (integer)
PHP 1500   → stored as 150000 (integer)

NEVER use JavaScript floating-point numbers for money calculations.
JavaScript: 0.1 + 0.2 = 0.30000000000000004 (wrong)
Correct:    10 + 20 = 30 centavos (integer math, always exact)

Display conversion (centavos → PHP display string):
  formatPHP(99900) → "₱999.00"
  formatPHP(150)   → "₱1.50"
```

## 3. Invoice Lifecycle

```
[DRAFT] → billing job creates it, not yet posted to ledger
[POSTED] → ledger entry created, subscriber owes this amount
[PARTIALLY_PAID] → some payment applied but balance remains
[PAID] → fully settled
[VOID] → reversed; original ledger entry cancelled by a credit
[OVERDUE] → past due date and not fully paid (status updated by a nightly check)
```

> **Why DRAFT → POSTED instead of posting immediately?**
> Admin/Billing Clerk can review generated invoices before they affect subscriber balances.
> In small offices this is common practice. The batch can be reviewed and then bulk-posted.
> For the demo, bulk-post is one button click.

## 4. Database Schema

```typescript
// apps/server/src/db/schema/billing.ts

import {
  pgTable,
  uuid,
  varchar,
  text,
  integer,
  date,
  timestamp,
  pgEnum,
} from "drizzle-orm/pg-core";
import { relations } from "drizzle-orm";
import { serviceAccounts } from "./subscribers";
import { users } from "./users";

export const invoiceStatusEnum = pgEnum("invoice_status", [
  "draft",
  "posted",
  "partially_paid",
  "paid",
  "void",
  "overdue",
]);

export const invoiceTypeEnum = pgEnum("invoice_type", [
  "monthly_subscription",  // Regular monthly bill generated by the billing job
  "reconnection_fee",      // Charged when a suspended account is reconnected
  "adjustment",            // Manual correction (with justification)
  "late_fee",              // Penalty for overdue account
]);

// ─── Invoices ─────────────────────────────────────────────────────────────────
export const invoices = pgTable("invoices", {
  id: uuid("id").primaryKey().defaultRandom(),

  // Human-readable invoice number — printed on documents
  // Format: INV-YYYY-MM-XXXXXX (e.g., INV-2025-01-000042)
  invoiceNumber: varchar("invoice_number", { length: 30 }).notNull().unique(),

  serviceAccountId: uuid("service_account_id").notNull().references(() => serviceAccounts.id),

  invoiceType: invoiceTypeEnum("invoice_type").notNull(),
  status: invoiceStatusEnum("status").notNull().default("draft"),

  // The billing period this invoice covers (for monthly subscriptions)
  // IMPORTANT: billing_period_year + billing_period_month together must be
  // unique per service account. This is the duplicate-prevention mechanism.
  billingPeriodYear: integer("billing_period_year"),   // e.g., 2025
  billingPeriodMonth: integer("billing_period_month"), // 1–12

  // Invoice dates
  invoiceDate: date("invoice_date").notNull(),         // When invoice was generated
  dueDate: date("due_date").notNull(),                 // When payment is due (e.g., 15th of month)

  // Financial totals (all in centavos)
  subtotalCentavos: integer("subtotal_centavos").notNull(),
  lateFeesCentavos: integer("late_fees_centavos").notNull().default(0),
  totalAmountCentavos: integer("total_amount_centavos").notNull(), // subtotal + late fees
  paidAmountCentavos: integer("paid_amount_centavos").notNull().default(0),
  remainingBalanceCentavos: integer("remaining_balance_centavos").notNull(), // total - paid

  // For voided invoices: the ID of the void transaction that reversed it
  voidedByTransactionId: uuid("voided_by_transaction_id"),

  // Internal notes (reason for manual adjustment, void reason, etc.)
  notes: text("notes"),

  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  postedAt: timestamp("posted_at", { withTimezone: true }),   // when status changed to POSTED
  voidedAt: timestamp("voided_at", { withTimezone: true }),

  createdBy: uuid("created_by").notNull().references(() => users.id),
  postedBy: uuid("posted_by").references(() => users.id),
  voidedBy: uuid("voided_by").references(() => users.id),
});

// ─── Invoice Line Items ───────────────────────────────────────────────────────
// An invoice can have multiple line items (subscription + late fee + etc.)
// This is for display on the invoice document; the total is on the invoice row.
export const invoiceLineItems = pgTable("invoice_line_items", {
  id: uuid("id").primaryKey().defaultRandom(),
  invoiceId: uuid("invoice_id").notNull().references(() => invoices.id),

  description: varchar("description", { length: 200 }).notNull(),
  // e.g., "Fiber 25Mbps — January 2025", "Late Fee", "Reconnection Fee"

  quantityCentavos: integer("quantity").notNull().default(1),
  unitAmountCentavos: integer("unit_amount_centavos").notNull(),
  totalAmountCentavos: integer("total_amount_centavos").notNull(),
});

// ─── Billing Run Log ──────────────────────────────────────────────────────────
// Records every time the monthly billing job ran — for audit and debugging.
export const billingRuns = pgTable("billing_runs", {
  id: uuid("id").primaryKey().defaultRandom(),

  billingPeriodYear: integer("billing_period_year").notNull(),
  billingPeriodMonth: integer("billing_period_month").notNull(),

  // Stats from the run
  totalServiceAccountsProcessed: integer("total_service_accounts_processed").notNull(),
  totalInvoicesGenerated: integer("total_invoices_generated").notNull(),
  totalInvoicesSkipped: integer("total_invoices_skipped").notNull(), // already had invoice
  totalAmountBilledCentavos: integer("total_amount_billed_centavos").notNull(),

  status: varchar("status", { length: 20 }).notNull(), // "completed" | "failed" | "partial"
  errorDetails: text("error_details"),

  ranAt: timestamp("ran_at", { withTimezone: true }).notNull().defaultNow(),
  ranBy: uuid("ran_by").notNull().references(() => users.id),
});

// ─── Relations ───────────────────────────────────────────────────────────────
export const invoicesRelations = relations(invoices, ({ one, many }) => ({
  serviceAccount: one(serviceAccounts, {
    fields: [invoices.serviceAccountId],
    references: [serviceAccounts.id],
  }),
  lineItems: many(invoiceLineItems),
}));
```

## 5. Invoice Number Generation

```typescript
// apps/server/src/modules/billing/invoice-number.service.ts

export function generateInvoiceNumber(
  year: number,
  month: number,
  sequenceNumber: number
): string {
  // Format: INV-2025-01-000042
  // Sortable, human-readable, identifies billing period at a glance
  const monthStr = String(month).padStart(2, "0");
  const seq = String(sequenceNumber).padStart(6, "0");
  return `INV-${year}-${monthStr}-${seq}`;
}
```

## 6. Monthly Billing Job

```typescript
// apps/server/src/modules/billing/monthly-billing.service.ts
// This is the most financially critical piece of code in the system.
// It must be correct, idempotent, and well-tested.

import { db } from "../../db/connection";
import { invoices, invoiceLineItems, billingRuns } from "../../db/schema/billing";
import { serviceAccounts } from "../../db/schema/subscribers";
import { eq, and, isNull } from "drizzle-orm";

export async function runMonthlyBilling(
  billingYear: number,
  billingMonth: number,
  initiatedByUserId: string
): Promise<{
  generated: number;
  skipped: number;
  totalBilledCentavos: number;
}> {
  // Step 1: Find all active service accounts
  const activeAccounts = await db
    .select({
      id: serviceAccounts.id,
      planId: serviceAccounts.planId,
      // plan details joined in
    })
    .from(serviceAccounts)
    .innerJoin(/* subscriptionPlans */)
    .where(eq(serviceAccounts.status, "active"));

  let generated = 0;
  let skipped = 0;
  let totalBilledCentavos = 0;

  for (const account of activeAccounts) {
    // Step 2: Check if invoice already exists for this period
    // This is the DUPLICATE PREVENTION check.
    const existingInvoice = await db
      .select({ id: invoices.id })
      .from(invoices)
      .where(
        and(
          eq(invoices.serviceAccountId, account.id),
          eq(invoices.billingPeriodYear, billingYear),
          eq(invoices.billingPeriodMonth, billingMonth),
          // Only check non-void invoices (a voided invoice should allow re-billing)
          // Note: in practice, voiding a monthly invoice is rare
        )
      )
      .limit(1);

    if (existingInvoice.length > 0) {
      skipped++;
      continue; // already billed for this period — skip silently
    }

    // Step 3: Generate the invoice in a transaction
    // Transaction ensures: if lineItems insert fails, invoice is also rolled back
    await db.transaction(async (tx) => {
      const dueDate = new Date(billingYear, billingMonth - 1, 15); // due on the 15th

      const [invoice] = await tx.insert(invoices).values({
        invoiceNumber: await getNextInvoiceNumber(tx, billingYear, billingMonth),
        serviceAccountId: account.id,
        invoiceType: "monthly_subscription",
        status: "draft",
        billingPeriodYear: billingYear,
        billingPeriodMonth: billingMonth,
        invoiceDate: new Date().toISOString().slice(0, 10),
        dueDate: dueDate.toISOString().slice(0, 10),
        subtotalCentavos: account.plan.monthlyRateCentavos,
        totalAmountCentavos: account.plan.monthlyRateCentavos,
        remainingBalanceCentavos: account.plan.monthlyRateCentavos,
        createdBy: initiatedByUserId,
      }).returning();

      await tx.insert(invoiceLineItems).values({
        invoiceId: invoice.id,
        description: `${account.plan.name} — ${getMonthName(billingMonth)} ${billingYear}`,
        quantity: 1,
        unitAmountCentavos: account.plan.monthlyRateCentavos,
        totalAmountCentavos: account.plan.monthlyRateCentavos,
      });
    });

    generated++;
    totalBilledCentavos += account.plan.monthlyRateCentavos;
  }

  // Step 4: Record the billing run for audit purposes
  await db.insert(billingRuns).values({
    billingPeriodYear: billingYear,
    billingPeriodMonth: billingMonth,
    totalServiceAccountsProcessed: activeAccounts.length,
    totalInvoicesGenerated: generated,
    totalInvoicesSkipped: skipped,
    totalAmountBilledCentavos: totalBilledCentavos,
    status: "completed",
    ranBy: initiatedByUserId,
  });

  return { generated, skipped, totalBilledCentavos };
}
```

## 7. Invoice Void Workflow

```typescript
// apps/server/src/modules/billing/void-invoice.service.ts
// Voiding creates a reversing ledger entry. The original invoice row stays.
// NEVER delete invoices.

export async function voidInvoice(
  invoiceId: string,
  reason: string,
  voidedByUserId: string
): Promise<void> {
  await db.transaction(async (tx) => {
    const [invoice] = await tx
      .select()
      .from(invoices)
      .where(eq(invoices.id, invoiceId))
      .limit(1);

    if (!invoice) throw new NotFoundError("Invoice not found");
    if (invoice.status === "void") throw new ConflictError("Invoice is already voided");
    if (invoice.status === "paid") {
      throw new ConflictError(
        "Cannot void a fully paid invoice. Use a payment reversal instead."
      );
    }

    // 1. Mark the invoice as void
    await tx
      .update(invoices)
      .set({
        status: "void",
        voidedAt: new Date(),
        voidedBy: voidedByUserId,
        notes: reason,
      })
      .where(eq(invoices.id, invoiceId));

    // 2. Create a reversing ledger entry (handled in Phase 6 — ledger module)
    await createLedgerReversal(tx, invoice, reason, voidedByUserId);
  });
}
```

## 8. Late Fee Application

```typescript
// apps/server/src/modules/billing/late-fee.service.ts
// Run after the due date. Finds overdue invoices and adds a late fee line item.

// Business rule: Late fee = fixed amount per overdue period.
// The late fee amount is configurable in system settings (Phase 9).
// Default: PHP 50.00 (5000 centavos) per month past due.

export async function applyLateFeesToOverdueInvoices(
  systemSettings: { lateFeeCentavos: number },
  appliedByUserId: string
): Promise<number> {
  // Find all posted invoices past due date with unpaid balance
  const overdueInvoices = await findOverdueInvoices();

  for (const invoice of overdueInvoices) {
    await db.transaction(async (tx) => {
      // Add late fee line item
      await tx.insert(invoiceLineItems).values({
        invoiceId: invoice.id,
        description: `Late Payment Fee — ${formatDate(new Date())}`,
        quantity: 1,
        unitAmountCentavos: systemSettings.lateFeeCentavos,
        totalAmountCentavos: systemSettings.lateFeeCentavos,
      });

      // Update invoice totals
      await tx
        .update(invoices)
        .set({
          lateFeesCentavos: invoice.lateFeesCentavos + systemSettings.lateFeeCentavos,
          totalAmountCentavos:
            invoice.totalAmountCentavos + systemSettings.lateFeeCentavos,
          remainingBalanceCentavos:
            invoice.remainingBalanceCentavos + systemSettings.lateFeeCentavos,
          status: "overdue",
        })
        .where(eq(invoices.id, invoice.id));

      // Also create a ledger debit for the late fee
      await createLateFeeledgerEntry(tx, invoice, systemSettings.lateFeeCentavos, appliedByUserId);
    });
  }

  return overdueInvoices.length;
}
```

```

POST /api/billing/apply-late-fees              → Apply late fees to overdue invoices
```

## 11. Acceptance Criteria

- [ ] Monthly billing job generates exactly ONE invoice per active service account per period
- [ ] Running the billing job twice in the same month does NOT create duplicate invoices
- [ ] Invoice numbers follow INV-YYYY-MM-XXXXXX format and are unique
- [ ] Invoice total = sum of line items (verified by unit test)
- [ ] All monetary values stored as integers in centavos
- [ ] Draft invoices do NOT affect subscriber ledger balance
- [ ] Posting an invoice creates a ledger DEBIT entry
- [ ] Voiding an invoice creates a ledger CREDIT entry and marks invoice as VOID
- [ ] Original invoice row is NEVER deleted from the database
- [ ] Late fee adds a line item and updates invoice totals
- [ ] Reconnection fee invoice is generated when a suspended account is reconnected
- [ ] Non-Billing Clerk roles cannot run the billing job
- [ ] Unit tests cover: billing calculation, duplicate prevention, void, late fee
